# OMSI HOF Maker v1.3

**OMSI HOF Maker by Super6uo** is a tool for creating KMB (Kowloon Motor Bus) and LWB (Long Win Bus) HOF files for **OMSI 2 / OpenOMSI**. It integrates Hoilun electronic destination-display data, generates DPIP images, and downloads and combines bus-stop announcement audio.

[**Download OMSI HOF Maker v1.3**](https://github.com/kowinleung/OMSI-HOF-Maker/releases)

> Before using the program, install the **KMB Electronic Display Integration Project (九巴電牌集成計劃)** and read its **Readme 2.0**. This prerequisite is specified in the user guide. The guide does not include a download URL for that package, so please obtain it from its original distribution.

## Features

- Create KMB and LWB HOF files for OMSI 2 / OpenOMSI.
- Retrieve route, service, stop and fare information from the Stopreporter database.
- Generate standard 6-word and 8-word HOF assets, as well as the All-In-One (AIO) HOF format.
- Support NewScript and Non-NewScript HOF output.
- Build outbound, inbound, single-direction and circular route sequences.
- Edit stop display names and multi-page display content.
- Configure special announcements (SPA) and sectional-fare stops.
- Download, validate and combine multilingual announcement recordings, with automatic timing calculation.
- Generate DPIP assets, including `LONG_route`, `LONG_stop_list`, `LONG_base_color`, `LONG_dot`, `LONG_5_stop` and `3_stop_mon`.
- Assign different HOF formats to individual buses through HOF Manager.
- Save and reload projects in JSON format.
- Verify generated assets and report missing audio or display files after export.

## Before you start

1. Install the **KMB Electronic Display Integration Project (九巴電牌集成計劃)** (https://docs.google.com/document/d/1oBtlMMRmlZ9S9s2M621aX3WXNBDktostIKE8SXTDTOA/edit?tab=t.0).
2. Read the integration project's **Readme 2.0** before generating HOF files.
3. Download OMSI HOF Maker from the [GitHub Releases page](https://github.com/kowinleung/OMSI-HOF-Maker/releases).
4. On the first launch, use **Link OMSI 2 Folder** to select your OMSI 2 installation directory. The application remembers the linked OMSI path for subsequent use.

The application can download the latest Stopreporter database automatically. Route and stop information is therefore normally retrieved by the application rather than requiring users to prepare a route database manually.

## Top toolbar and export options

| Control | Description |
|---|---|
| **HOF File Output Name** | Sets the name of the final generated `.hof` file. |
| **Load Project / Save Project (.json)** | Loads or saves the current project configuration and progress as a JSON file so work can be continued later. |
| **Link OMSI 2 Folder** | Selects the OMSI 2 installation directory. The application remembers the selected path. |
| **Stopreporter Database** | Downloads the latest Stopreporter database for route and stop information. |
| **Clear All Data** | Clears the current data and resets the application state. |
| **Generate DPIP Only** | Generates DPIP images without running the full HOF export. |
| **Generate HOF Files** | Runs the complete export workflow: generates the selected HOF format(s), downloads or creates announcement and display assets, generates DPIP images and exports the files. |
| **Clean Exported Files** | Removes `.hof`, audio and image files previously generated by this application from the relevant output locations. |
| **Generate All-In-One HOF** | When selected, generates a single AIO HOF file. The guide describes this format as suitable for both NewScript and Non-NewScript buses, with better results when used with NewScript buses. |
| **Generate both NewScript and Non-NewScript** | Generates both the legacy and NewScript V2 HOF formats. |
| **Settings** | Checks for application updates and allows the user to select the public or test/pre-release update channel. |

> The two HOF output options control the export format. Select the format required by the buses you intend to use.

## Workflow

### Tab 1 - Route Setup

Use **Route Setup** to create routes and configure their direction, route mode and destination displays.

#### Creating routes

- **Create New Route**: Enter a route number. The application queries the route API and presents the available service types or special services for selection.
- **Browse All Routes**: Browses routes available in the Stopreporter database, including special services.
- **Route list**: Displays routes already added to the project. Drag and drop entries to change their order in the generated HOF. Use the delete control beside a route to remove it.

**Route IDs must be unique.** If you are creating both a normal service and a special service with the same route number, manually rename one of the route IDs so they do not conflict.

#### Route modes

The application attempts to detect whether a route is circular or operates in one direction. You can change the mode manually when necessary.

| Mode | Behaviour |
|---|---|
| **Normal** | Standard outbound and inbound route. |
| **Single Direction** | One-way service. The inbound direction is locked and set to `Wrong Way`. |
| **Circular** | Combines outbound and inbound into one sequence. It uses the outbound welcome announcement and inbound thank-you announcement, and synchronises the starting stop name as the DPIP destination. |

#### Destination and display controls

- **Swap DDU Name**: Swaps the outbound and inbound DDU destination names.
- **Swap Display**: Swaps the outbound and inbound destination-display and code configuration.
- **Base Display / BusFull Display**: Use the folder button beside a field to select a standard or full/overcrowded display image manually.
- After a Base Display is selected, the application scans the same directory for a matching BusFull directory and additional pages such as `_2` and `_3`, then assigns the corresponding display files automatically.

### Tab 2 - Addbusstop Setting

Use **Addbusstop Setting** to manage bus stops used in the HOF, including English and Chinese display names and display page counts.

#### Adding and reloading stops

- **Manual Add bus stops**: Adds a stop or special announcement that cannot be found through the route API.
- Select **Add as special stop** to add the `__` prefix to the handle and create an announcement-only stop.
- **Reload Route Data**: Rebuilds route data, including stops, fares and sectional fares.

#### Editing stop information

The application generates stop display information in the Stopreporter database format. Manual editing is normally unnecessary, but you can double-click display text or open the **Multi-Page Editor** to adjust it.

| Field | Description |
|---|---|
| **Handle** | Filename/identifier used for the stop's display and audio assets. |
| **8 Word CHI / 6 Word Chi / English Displays** | Double-click to edit the corresponding display text. |
| **8W Pgs / 6W Pgs** | Sets the number of display pages (1 to 3). |
| **Edit Pages** | Opens the Multi-Page Editor to edit each page's optional Line 0 and Line 1 content independently. |

For the Multi-Page Editor, the guide recommends normally entering content in **Line 1** only. Adding Line 0 may cause the actual announcement display to use an incorrect format.

**English DPIP 8-word limitation:** The LCD/DPIP 8-word English display does not support paginated English announcements. If the English display contains more than one line (separated by `@`), the application highlights it. This highlight can be ignored if the result is acceptable for your setup.

#### LWB welcome announcement conversion

When a new route is created with a route number beginning with `A`, `E`, `S`, `R` or `NA` (for example, `A41P`, `E36` or `NA33`), the application detects it as an LWB route and automatically changes the welcome-announcement display text to the LWB wording:

- Chinese: `歡迎乘坐龍運巴士`
- English: `WELCOME ONBOARD LONG WIN BUS`

No manual text replacement is normally required.

### Tab 3 - Stop Sequence Builder

Use **Stop Sequence Builder** to arrange the actual stop order and configure announcement and sectional-fare behaviour.

#### Arranging the sequence

- Drag stops from the **SPA / Normal Stop** lists on the right into the sequence table.
- Use the search field to find a stop quickly.
- Use **Up / Dn** to move the selected stop earlier or later in the sequence.
- Use **Switch to Inbound / Outbound** to change the direction being edited.
- **Undo / Redo** supports repeated undoing and redoing of sequence changes.

#### Stop attributes

- **SPA (Special Announcement)**: Marks an entry as a special announcement. The SPA behaviour controls whether the normal `__ATTEN10010` handrail announcement is inserted after the special announcement. The sequence preview and exported HOF follow the selected setting.
- **Sect (Sectional Fare)**: Marks a stop as a sectional-fare point. The application automatically inserts the `__SECT100010` cue before the relevant point.
- **Fare**: The application fills in the sectional fare amount and adds the corresponding sectional-fare `[addbusstop]` entry.

For circular routes, the application automatically inserts the `__DingDong2` announcement at the appropriate position.

### Tab 4 - StopReporter Audio Generator

Use **StopReporter Audio Generator** to retrieve and combine the separate language recordings for each stop and calculate the required playback time.

The application downloads recordings from the Stopreporter database automatically. Some stops may not have recordings available; use the audio status information to identify those cases.

- **Refresh Audio Link Status**: Rechecks the audio database and refreshes the status shown in the audio list.
- If a recording is marked **Missing**, click its Audio A, B or C link to open the corresponding audio source in your web browser.
- **Manual Link**: If the source filename does not match the stop name and the application cannot locate it automatically, select the stop's `_A` or `_B` recording manually. The application then links the remaining language components automatically.

### Tab 5 - HOF Manager

Use **HOF Manager** to assign HOF formats to individual buses.

The application displays detected or configurable bus folders. Assign the HOF format required by each bus; the application will generate and install the corresponding HOF files into the selected bus folders during export.

Set a bus to **None** if you do not want the application to install a HOF file for that bus. Buses assigned to `None` are skipped during installation.

## DPIP generation

The application includes a native DPIP image-generation engine. During export, it reads the outbound and inbound terminal names configured in Tab 2 and generates the DPIP assets automatically.

Generated assets include:

- `LONG_route`
- `LONG_stop_list`
- `LONG_base_color`
- `LONG_dot`
- `LONG_5_stop`
- `3_stop_mon`

The generator uses **Microsoft JhengHei** for text rendering. The guide notes that fonts generated by Python may differ slightly from manually produced fonts.

You can use **Generate DPIP Only** when you only need to regenerate the DPIP images rather than exporting the complete HOF package.

## Compile and export

Before exporting, check that the route configuration, stop displays, stop sequence and audio status are correct.

1. Click **Generate HOF Files**.
2. If audio files are missing, the application asks whether you want to continue.
3. Choose the default OMSI destination folder or select a custom export directory. For a custom directory, the application creates the required folder structure, including folders such as `Vehicles/GX7767Electronics`.
4. If output files already exist, the application asks whether they should be overwritten.
5. The application generates BMP display images, combines multilingual announcement audio, generates DPIP images and writes the HOF file(s).
6. When export is complete, an **Asset Verification Report** appears. It identifies announcement audio or display files that are still missing so that they can be checked and replaced.

Review the Asset Verification Report after each export, especially when the selected route contains special announcements or recordings that are not available in the Stopreporter database.

## FAQ and troubleshooting

### A circular route has some announcements with no sound or display

This can be caused by an OMSI limitation involving the number of `[addbusstop]` entries. If the route has more announcement entries than `[addbusstop]` entries, announcements beyond the available entries may have no display or sound. For example, the guide illustrates a case with 30 announcements but only 20 `[addbusstop]` entries.

**Suggested workaround:** Add more `[addbusstop]` entries. The guide suggests copying additional entries from another HOF file. Avoid creating only a single circular route in isolation when possible.

### The welcome and thank-you announcements are in the opposite direction

KMB route data and the KMB electronic-display integration data may occasionally use different destination directions. The guide gives route 671Y as an example of this kind of mismatch.

**Suggested workaround:** Check the outbound/inbound destination assignment in Route Setup. Use **Swap DDU Name** and **Swap Display** as appropriate, then verify the sequence and `[addbusstop]` order. If the welcome and thank-you entries in `[infosystem_busstop_list]` are still reversed, return to Route Setup and check both swaps again.

### How do I use a custom destination display?

Some routes may not have a display image in the KMB Electronic Display Integration Project. The guide gives route `A41P` as an example.

**Suggested workaround:** In Route Setup, use the folder button to select the custom Base Display image. If the route has several display files, select the main destination image (for example, `6XY.bmp`). The application scans the directory for related files such as `6XY_2.bmp` and assigns the additional pages automatically.

### An audio recording is missing

Open Tab 4 and use **Refresh Audio Link Status**. Click the Audio A/B/C entry to open the source link in a browser. If the filename does not match the stop name, use **Manual Link** to select the matching `_A` or `_B` audio file.

### A stop display needs more than one page

Use the page-count fields in Tab 2 to set the required number of pages (1 to 3), then open **Edit Pages** to edit the individual page content. The guide recommends using Line 1 only unless Line 0 is specifically needed.
